# Bot 对战与回放实施计划

> 当前状态为已完成。3 项均已实现并验证。Rust 工作区测试、Clippy、真实 C ABI 测试、离线回放和静止靶 Chromium 验收均通过。审查后补测了裁判退出清理和导出失败，计分权重和步数上限随观测提供给 bot。

**目标**是让四个 bot 完成一场有计分且可以离线播放的比赛。

**设计**见 [Bot 对战与回放设计](../specs/2026-11-25-bot-match-design.md)。Rust 核心统一规则，裁判负责延迟观测、运行控制器、记分和导出，Canvas 只绘制已记录的实时帧。

## 实施步骤

- [x] **1. 多席位核心。** 在 `arena-core` 增加 `Round::with_players`，将动作、出生、碰撞与道具处理推广到 2–4 个稳定席位。对局结果包含获胜席位，逐步输出淘汰事件及其发射者。用三、四席与最后一个生存者的回归用例驱动实现。保持双席地图与试玩消息兼容，运行核心和试玩测试。
- [x] **2. 裁判和 C ABI。** 新增 `arena-runner`，每步从 12 步历史里构造 bot 观测，单独提供当前自身。实现每步裁判计分及回合时限。用 Linux worker 加载 C 库，出错或超时采用空操作。用延迟边界、计分和真实测试库验证。
- [x] **3. 回放与验收。** 导出版本化的 JSON 与自包含 HTML，共用 Canvas 绘制。运行四席比赛，检查回放进度、倍速与最终计分。复查现有试玩和文档，提交并合并任务分支。
