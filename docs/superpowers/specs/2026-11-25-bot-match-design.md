# Bot 对战与回放设计

## 对局入口

由无界面裁判驱动 Rust 核心。每场 2–4 辆坦克，席位按命令行顺序编号，各有合法且互相分开的出生点。浏览器静止靶练习继续使用同一核心与原有操作。真人共局适合试玩驾驶，直接驱动核心则能先验证 bot 决策、计分和回放的完整流程，因此先提供无界面裁判。

同一种子和参数下，对已采用的逐步操作重新执行规则，可以复现比赛。每步先生成各席位读到的局面，再调用 bot，再统一执行所有操作。核心保持每秒 60 步。剩一辆坦克时留出 120 步，最后一步先判命中，再判胜负。全灭立即平局。为结束长期僵持，裁判在可配置的模拟步上限判平局，若届时已进入最后 120 步则完成该阶段。

## 决策与观测

- 当前模拟步为 `t` 时，控制者看到本步自己的坦克以及 `max(0, t−12)` 的其他坦克、道具、弹丸和激光轨迹。自己的弹丸和轨迹也使用延迟帧。地图、规则参数与席位编号固定。观测标记当前步号和延迟帧步号。出局席位停止调用。
- 每场第一次决策限 100 ms，以后每次限 30 ms，按墙钟测量。每次可组合 W、S、A、D 和单次开火。非法返回、崩溃或超时当步执行空操作，并记录诊断。超时后结束该 worker，下一步按剩余席位重新启动，决策额度按比赛步号计算。
- Linux 裁判把动态库放在独立 worker 进程中运行，由 C ABI 导出版本与决策函数。调用期间借用 UTF-8 JSON 观测，函数返回操作位。worker 在调用间暂停。示例控制器用于验证流程和复现比较。

## 计分与回放

- 摧毁别的坦克时给弹丸或激光轨迹的发射者加击杀分，反弹和发射者出局不改变归属。自己击毁自己的坦克为零分。每个目标只归属一次，同一步多个命中按确定的碰撞遍历顺序取首个归属。最终存活者单独获得存活分，平局没有存活分。初始每次击杀和最终存活各值 1 分，由裁判参数调整。
- 每场导出 `replay.json` 与自包含 `replay.html`。日志保存规则、种子、席位、截止步、实际执行的操作、逐步实时画面、击杀归属和结算结果。回放的 1 倍速每秒播放 60 步，提供暂停、调速和跳转，离线打开时只读取日志。
- 验收包括 2、3、4 席确定性、击杀和自杀归属、最终存活计分、12 步延时边界、真实 C 库和超时路径，以及直接打开一场四席比赛的回放。
