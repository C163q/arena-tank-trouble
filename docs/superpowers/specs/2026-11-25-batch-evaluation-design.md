# 批量测评与逐步回放设计

默认击杀分为 1，最终存活分为 2。保留裁判覆盖权重的参数。

参考同工作区 fight-for-flags 的逐步文本、通用播放器和批量裁判。当前裁判已生成可视画面和执行后的动作。逐步文本从同一份真实帧导出，避免维护另一套模拟。静态数据和列名放在首行，随后每模拟步一行，最后一行给出结果。用列注明含义的数组表达坦克、弹丸、激光轨迹、道具、采用的动作和淘汰归属，保留完整坐标精度。输出名为 `timeline.jsonl`。

通用离线播放器可通过裁判导出，允许选择或拖入 `replay.json` 或 `timeline.jsonl`，载入时重置进度。分享用的独立 `replay.html` 从同一模板导出，附带该局数据。导入错误留在页面中提示，保留先前可用的回放。

批量入口使用 Python 标准库启动现有 `arena-runner`，同一赛程可用不同并行数。每场 2–4 席，支持更大的输入池。优先安排出场少的 AI，同等出场时优先减少重复同场。每组使用同一种子轮换出生位，直至达到所请求的总局数。末组可能少于一次完整轮换。赛程根据种子固定。总榜保留出场数、胜场、击杀和存活分；按场均总分排名，同分并列。每局保留裁判输出和错误日志，汇总中标记失败场。并行度是同时运行的独立对局数。

验收覆盖一局真实 C ABI、文本还原、拖入与换局、无效文件处理、以两个并行槽运行含多份共享库的测评，并复核逐局分数和总榜。
