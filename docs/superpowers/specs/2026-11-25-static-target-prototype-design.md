# 静止靶试玩版设计

## 目标与方案

首版提供本地浏览器试玩。玩家用键盘操控一辆坦克，在随机迷宫中向一辆静止靶射击。试玩用于调整移动、转向、补弹和反弹手感。阶段验收以能完成一次完整的练习和重复比较参数为准。

静止靶便于在同一位置重试操作，也便于看清弹道。可移动、会开火的陪练适合检验实战手感，可在基础操作稳定后加入。激光和其他道具、原生 C ABI 及正式竞赛规则属于后续阶段。

本地 Rust 程序运行模拟并通过 WebSocket 接收操作、发送局面。浏览器使用 Canvas 绘制，日后原生裁判也可调用同一个 Rust 核心。WebAssembly 适合静态网页独立试玩，原生 bot 仍需要原生加载入口。首版采用本地 Rust 程序以便复用原生模拟入口。

## 一局练习

- 进入页面后自动开启一局。地图是带封闭外边界的连通网格迷宫。Rust 根据种子生成内墙、相隔若干格的两个出生位置及各自的初始朝向。双方在合法格心出生，保持与墙和彼此的间距。
- W 沿车头方向前进，S 后退，A 绕中心逆时针转动，D 顺时针转动。移动和转向可以同时进行，同一轴的相反输入互相抵消。坦克不能穿过墙或另一辆坦克。静止靶全程采用空操作。
- 空格每次按下请求开火一次，长按的系统按键重复不产生额外请求。一局开始时弹匣装满 5 发，成功射击消耗 1 发。弹匣首次低于满额时开始计时，每经过一个完整补弹间隔恢复 1 发，补满后计时停止。空仓时的开火请求当步丢弃。
- 普通弹沿车头方向飞行，碰墙后按入射方向和墙面反射，累计触墙达到上限时立即消失。弹丸发射后可以击中靶，至少完成一次反弹后也能击中自己。模拟按单步内的运动路径检查墙和坦克，避免高速弹丸跨过碰撞体。
- 贴墙时仍可开火并消耗 1 发。从坦克内部沿车头方向检查到炮口的路径，炮口处或途中遇到的第一面墙算一次触墙，当场按普通弹规则反弹或消失。
- 单次命中结束本局，画面停在结果处。记录靶被击中和玩家被自己的反弹弹击中两种结果。同一步内两者都被击中时记为平局。页面上的两项计数分别累计单独击中静止靶和单独击中自己的局数。
- 「同图重开」复用种子、出生位置和初始朝向，保留计数，并清空弹丸和操作，恢复满弹匣。「换图重开」使用新种子并清空计数。玩家可以在练习中随时使用这两个按钮。

## 试玩参数与界面

参数在页面填写，经 Rust 校验后随任一重开操作一起生效。修改输入框时，当前练习继续使用已生效的参数。下列数值是实现用的起点，试玩后可调整。

| 参数 | 初始值 |
| --- | --- |
| 前进一格所需时间 | 0.45 秒 |
| 后退一格所需时间 | 0.65 秒 |
| 原地转一圈所需时间 | 1.5 秒 |
| 恢复 1 发的间隔 | 1.0 秒 |
| 弹丸消失前的最大触墙次数 | 5 次 |

页面上方为浅底、深色墙线的迷宫，占主要空间。场内用原创俯视图形和两种颜色区分玩家与靶，并画出车头朝向。使用独立生成的地图。迷宫下方显示玩家的五格弹量、命中靶和反弹自伤计数。边上提供按键提示、种子、回合结果和重开控件。参数编辑区位于游戏区域之外，编辑时按键用于输入。

## 模拟与浏览器接口

- Rust 核心持有地图、随机种子、规则参数和状态。每秒推进 60 个等长模拟步，输入为每辆坦克的移动、转向和单次开火请求。相同的种子、参数和逐步输入在同一构建下应产生相同结果。核心可在没有 HTTP 服务器或浏览器的情况下运行。
- 本地程序只监听回环地址，从同一来源提供页面和 WebSocket。每个页面连接有自己的试玩状态。WebSocket 用 JSON 发送按键状态、开火和重开请求，服务端返回局面快照、结果和校验错误。无效参数保留当前局面和参数，并给出可见提示。
- 浏览器按屏幕刷新绘制最新快照，规则以 Rust 状态为准。窗口失焦或打开参数编辑区时清空按住的操作。重开时清除旧局输入，等待新的按键。断线时页面显示连接状态，并提供重新开始的入口，重连建立新的练习。
- 实现时确定具体的迷宫生成算法、坦克与弹丸碰撞尺寸、弹速、可调参数范围和消息字段。它们应满足上述试玩流程及验证条件。

## 验证

- 在 Rust 中验证同一种子的地图与出生位置可复现，出生点合法且相通。检查同时移动转向、阻挡、5 发弹匣、补弹、贴墙开火、反弹上限，以及命中靶和反弹自伤。
- 在浏览器里用 WASD 和空格跑通一局。检查画面、弹量和计数随服务端状态更新，命中后停止，同图重开复用出生状态，换图重开清空计数。检查调参生效、失焦释放操作以及断线提示。
- 真人试玩判断前进、后退、转向和补弹的时间，以及触墙上限是否合适。道具和 bot 的验收留到各自的设计阶段。
